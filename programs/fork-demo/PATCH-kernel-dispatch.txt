PATCH: FORK_SNAPSHOT (31) + EXEC_REPLACE (32) im Kernel verdrahten
=====================================================================
Stand: HEAD am 2026-09-09, Zweig arch/x86_64. ABI (31/32, ERR_STALE_TOKEN=26,
ERR_SNAPSHOT_LIMIT=27), Loader-Pruefung (cost/exec/snapshot) und
Microkit-Vorpruefung (proc::dekodiere_fork/exec, fail-closed BADSYS) liegen
bereits im Baum und sind host-geprueft. Was fehlt, sind die zwei Rueckrufe im
Kernel — deshalb ist 31/32 aus Kernelsicht heute BADSYS (Antrag ok, Pfad fehlt).

Dateibesitz beachten (AGENTS.md): kernel/src/system.rs ist GETEILT (A: Syscall-/
Cap-/Loader-Pfade — dieser Patch liegt darin), crates/caprock-microkit ist A-Besitz
(Cspace-Strang ausgenommen). Vor dem Anfassen Mitteilung an B. Beide Dateien
gehoeren in DENSELBEN Commit (Regel 3: sonst baut HEAD nicht — die erweiterte
Dispatch-Signatur ohne Aufrufer und umgekehrt). Commit-Identitaet nach Regel 4,
NICHT pushen (Regel 5).

TEIL 1/2 — crates/caprock-microkit/src/lib.rs (Dispatch-Signatur erweitern)
---------------------------------------------------------------------

Kontext: `pub fn dispatch` (heute 11 Parameter, letzter `bind_irq`), und
`fn dispatch_nativ` mit denselben Rueckrufen. Anker: Zeile mit
`bind_irq: fn(u32, usize, u64, usize) -> Result<(), u64>,` kommt zweimal vor
(je einmal in `dispatch` und in `dispatch_nativ`).

1a) In BEIDEN Signaturen nach der `bind_irq`-Zeile anfuegen:

    // Prozessmodell FORK/EXEC (31/32): die Rueckrufe liegen im Kernel, weil nur er
    // weiss, ob ein Geraet die Region erreicht, was die Ziel-VSpace enthaelt und wo
    // das Archiv liegt. Beide laufen OHNE gehaltenes `CAPS` (Ordnung MEM < SCHEDS).
    fork: fn(usize, usize, u64, u8) -> Result<u64, u64>,
    exec: fn(usize, CapPtr, u32, u64) -> Result<(), u64>,

   Dabei heisst bei `fork`: `(Aufrufer-PD, Kind-Slot, max_len, prio) -> Ok(Kind-PD-Id)`;
   bei `exec`: `(Aufrufer-PD, Loader-Cap, Archiv-Index, Token) -> Ok(())`.

1b) Die zwei Aufrufe von `dispatch_nativ` in `dispatch` (Weiche `Kernel`-Zweig und
    Schlusszeile) bekommen `fork, exec` angehaengt — dieselbe Reihenfolge wie in
    der Signatur.

1c) Die fail-closed Zweige `sys::FORK_SNAPSHOT` / `sys::EXEC_REPLACE` in
    `dispatch_nativ` (heute: Vorpruefung via `proc::dekodiere_*`, danach
    `deny(result::ERR_BADSYS)`) bekommen statt des BADSYS-Ausgangs den Rueckruf:

    sys::FORK_SNAPSHOT => {
        let m0 = frame_reg(frame, reg::MSG0);
        let m1 = frame_reg(frame, reg::MSG0 + 1);
        let m2 = frame_reg(frame, reg::MSG0 + 2);
        let m3 = frame_reg(frame, reg::MSG0 + 3);
        match proc::dekodiere_fork(m0, m1, m2, m3) {
            proc::ForkExecEntscheid::Abgewiesen(code) => deny(code),
            proc::ForkExecEntscheid::Fork(a) => {
                let thread = ops.current_id(core);
                let pd = {
                    let g = caps.read();
                    match g.pds.pd_of(thread) {
                        Some(pd) => pd,
                        None => return deny(result::ERR_NOPD),
                    }
                }; // CAPS freigegeben -- `fork` nimmt CAPS/MEM/SCHEDS selbst
                match fork(pd, a.kind_slot, a.max_len, a.prio) {
                    Ok(kind_pd) => {
                        frame_set_reg(frame, reg::MSG0, kind_pd as u64);
                        frame_set_reg(frame, reg::SYSNO_RESULT, result::OK);
                        frame
                    }
                    Err(code) => deny(code),
                }
            }
            proc::ForkExecEntscheid::Exec(_) => deny(result::ERR_BADCAP),
        }
    }
    sys::EXEC_REPLACE => {
        let x1 = frame_reg(frame, reg::EP_BADGE);
        let m0 = frame_reg(frame, reg::MSG0);
        let m1 = frame_reg(frame, reg::MSG0 + 1);
        let m2 = frame_reg(frame, reg::MSG0 + 2);
        let m3 = frame_reg(frame, reg::MSG0 + 3);
        match proc::dekodiere_exec(x1, m0, m1, m2, m3) {
            proc::ForkExecEntscheid::Abgewiesen(code) => deny(code),
            proc::ForkExecEntscheid::Exec(a) => {
                let thread = ops.current_id(core);
                let (pd, cap) = {
                    let g = caps.read();
                    let Some(pd) = g.pds.pd_of(thread) else {
                        return deny(result::ERR_NOPD);
                    };
                    let Some(cap) = g.pds.cap_at(pd, a.loader_slot) else {
                        return deny(result::ERR_BADCAP);
                    };
                    (pd, cap)
                }; // CAPS freigegeben -- `exec` nimmt CAPS/MEM/SCHEDS selbst
                match exec(pd, cap, a.prog_index, a.token) {
                    Ok(()) => deny(result::OK),
                    Err(code) => deny(code),
                }
            }
            proc::ForkExecEntscheid::Fork(_) => deny(result::ERR_BADCAP),
        }
    }

TEIL 2/2 — kernel/src/system.rs (zwei Rueckrufe + Aufrufstelle)
---------------------------------------------------------------------

2a) Aufrufstelle `fn syscall` (heute: `dispatch(..., sys_load_uebergeben,
    dispatch_delete_cap, dispatch_spawn, dispatch_debug, dispatch_bind_irq)`):
    zwei Argumente anhaengen: `dispatch_fork, dispatch_exec` (Definitionen s. 2c).

2b) Neue Helfer neben `loaded_register` (Zeile ~4975, ausserhalb `selftest`):

    /// Die registrierten (Phys-)Frames einer `asid` lesen — die Quellmenge des FORK.
    /// Spiegel von `loaded_frames_of`, aber NICHT hinter `selftest`: der FORK-Pfad
    /// braucht sie im Produktivbau. Gibt die Zahl der geschriebenen Eintraege.
    fn loaded_snapshot(asid: u16, out: &mut [(u64, u64)]) -> usize {
        let t = LOADED_IMAGES.lock();
        let Some(slot) = t.iter().position(|i| i.asid == asid && i.asid != 0) else {
            return 0;
        };
        let n = t[slot].nseg.min(out.len());
        out[..n].copy_from_slice(&t[slot].segs[..n]);
        n
    }

    /// Teardown-Epoche je PD fuer das EXEC-Token (monoton je PD, Start 0).
    /// 10 000 Eintraege = 40 KiB BSS; die Laenge folgt `NPDS` aus microkit.
    static EXEC_EPOCHE: SpinLock<[u32; caprock_microkit::NPDS]> =
        SpinLock::new([0; caprock_microkit::NPDS]);

2c) Neue Rueckrufe hinter `dispatch_spawn` (Zeile ~3707, vor `spawn_with_stack_parked`):

    /// `FORK_SNAPSHOT`: volle Kopie des Quell-Raums in eine frische Kind-PD (Phase 1).
    /// Kein COW (s. loader::snapshot-Doku: Dirty-Tracking + Fault-Pfad fehlen).
    /// Das Kind startet PARKIERT (D0) — erst PDCTL/START laesst es laufen.
    fn dispatch_fork(
        pd: usize,
        kind_slot: usize,
        max_len: u64,
        prio: u8,
    ) -> Result<u64, u64> {
        use caprock_abi::result;
        // Aufrufer-Domaene + Budget erben; Kind-Slot muss im Aufrufer-Cspace frei sein.
        let (domain, budget) = {
            let g = CAPS.read();
            let Some(d) = g.pds.domain_of(pd) else { return Err(result::ERR_NOPD) };
            if g.pds.cap_at(pd, kind_slot).is_some() { return Err(result::ERR_NOSPACE) };
            (d, g.pds.budget_of(pd))
        };
        // Quellmenge: registrierte Frames der eigenen ASID (Teardown-Buchhaltung —
        // was dort nicht steht, gehoert der PD nicht und wird nicht kopiert).
        let caller_tid = SCHEDS[hal::cpu::core_id()].lock().current_id(hal::cpu::core_id());
        let asid = (vspace_of(caller_tid.slot()) >> 48) as u16;
        if asid == 0 { return Err(result::ERR_NOPD) }
        let mut segs = [(0u64, 0u64); MAX_IMG_SEGS];
        let n = loaded_snapshot(asid, &mut segs);
        if n == 0 { return Err(result::ERR_NOPD) }
        // Rein pruefen, bevor irgendetwas alloziert ist (loader::snapshot ist kanonisch).
        let mut plan = [caprock_loader::snapshot::SnapSeg { va: 0, len: 0 }; MAX_IMG_SEGS];
        let mut sum = 0u64;
        let mut i = 0;
        while i < n {
            // VA steht nicht in der Buchhaltung (nur Phys-Frames) — die Abbildung
            // laeuft ueber die Ziel-VAen aus `loaded_register`? NEIN: ehrlich wir
            // kopieren phys->phys in die NEUE VSpace an DIESELBEN VAs. Dazu die VAs
            // aus den Quell-Tabellen ruecklesen geht nicht — also gilt: FORK kopiert
            // die Stack- + Segment-Frames an identische VAs; was der Aufrufer darueber
            // hinaus gemappt hat (MAP), wird NICHT kopiert und im Kind als Luecke
            // sichtbar (DEBUG_READ_MEM-Semantik: Luecke sehen, nicht raten).
            // Die VA-Liste liefert `pd_mapping_liste` — s. Kommentar unten.
            i += 1;
        }
        // NOTE (ehrlich, vor dem Commit zu schliessen): die VA-Rueckabbildung
        // phys->VA existiert heute NICHT (kein inverser Index). Zwei Wege:
        // (1) `load_into_pd_mit` um einen `va_liste`-Rueckgabepfad erweitern und in
        // `loaded_register` mittragen (bevorzugt: eine Wahrheit statt zwei), oder
        // (2) nur Stack + LOADED-Fenster an festen VAs kopieren (LOADED_STACK_VA ist
        // konstant, Segment-VAs stehen im ELF — ueber `read_archive` + program(index)
        // erneut lesbar). Bis dahin: ERR_NOSPACE ist falsch, richtig ist ERR_BADSYS
        // mit Kommentar — der Pfad meldet „noch nicht verdrahtet", nicht „kein Platz".
        let _ = (kind_slot, max_len, prio, budget, domain, sum, plan);
        Err(result::ERR_BADSYS)
    }

    HINWEIS ZU dispatch_fork: der Rumpf oben ist bewusst ein benanntes Geruest, kein
    Kopierloop mit erfundenen APIs — die VA-Rueckabbildung fehlt nachweislich (kein
    inverser Index im Baum; `vspace_resolve` geht nur VA->PA). Wer den Loop schreibt,
    ohne sie zu schaffen, kopiert an geratene VAs — das ist der Korruptionspfad, nicht
    die Abkuerzung. Die ehrliche Reihenfolge steht im NOTE.

    /// `EXEC_REPLACE`: neues Image in die BESTEHENDE PD laden (Teardown-Token-Form).
    fn dispatch_exec(
        pd: usize,
        loader_cap: caprock_cap::CapPtr,
        prog_index: u32,
        token: u64,
    ) -> Result<(), u64> {
        use caprock_abi::result;
        // 1. Loader-Autoritaet: Loader-Art + WRITE (dieselbe Pruefung wie SYS_LOAD).
        {
            let g = CAPS.read();
            match g.cspace.lookup(loader_cap) {
                Some((caprock_cap::ObjectKind::Loader { .. }, r, _))
                    if r.contains(caprock_mem::Rights::WRITE) => {}
                _ => return Err(result::ERR_BADCAP),
            }
        }
        // 2. Token gegen (program_id, Epoche): 0 ist kein „egal".
        if token == 0 { return Err(result::ERR_STALE_TOKEN) }
        let me = SCHEDS[hal::cpu::core_id()].lock().current_id(hal::cpu::core_id());
        let prog_id = crate::loader::program_of_thread(me).unwrap_or(u32::MAX);
        let epoche = EXEC_EPOCHE.lock()[pd % caprock_microkit::NPDS];
        if token != caprock_loader::exec::teardown_token_fuer(prog_id, epoche) {
            return Err(result::ERR_STALE_TOKEN);
        }
        // 3. Programm aufloesen (Archiv-Index -> Program; dieselbe Quelle wie reload_driver).
        let prog = {
            let Some(arch) = crate::loader::read_archive() else {
                return Err(result::ERR_BADCAP);
            };
            match arch.program(prog_index as usize) {
                Some(p) => p,
                None => return Err(result::ERR_BADCAP),
            }
        };
        // 4. Geordneter Rueckzug: fremde Threads abziehen, Slots loeschen (ausser dem
        //    Slot der Loader-Cap), Mappings der alten Fassung loesen. DANN laden.
        //    (Reihenfolge s. loader::exec-Doku: erst 1-3, dann load_program_into_pd.)
        //    Epoche erst nach erfolgreichem Laden heben — sonst verliert ein Fehlschlag
        //    das Token der noch laufenden alten Fassung.
        match crate::loader::load_program_into_pd(&prog, pd, &[], 0) {
            Some(_) => {
                EXEC_EPOCHE.lock()[pd % caprock_microkit::NPDS] =
                    epoche.wrapping_add(1).max(1);
                Ok(())
            }
            None => Err(result::ERR_NOSPACE),
        }
    }

    ANMERKUNG ZU SCHRITT 4 (vor dem Commit mit A abzustimmen): `load_program_into_pd`
    legt neue VSpace/Thread AN STATT die bestehende PD-Zelle wiederzuverwenden und
    raeumt weder Fremd-Threads noch alte Slots — der geordnete Rueckzug (KILL +
    clear_cap-Schleife ausser Loader-Slot) fehlt im Rumpf oben und ist vor der
    Abnahme zu ergaenzen (Sperrordnung CAPS < SCHEDS beachten, CAPS je Schritt kurz
    halten wie in dispatch_spawn). Bis dahin faellt EXEC bei belegter PD mit
    ERR_NOSPACE statt still zu ueberresten — fail-closed, aber unvollstaendig, und
    das steht hier statt im Log.
